# Experiments

Two bodies of work live here. **The current one** is the strict 4-hop campaign on the
helixon cluster: seven scenes, four agent×channel arms, two checkpoints, 49 episodes, all
scored and all traced. **The earlier one** is the DeltaAI campaign, kept because its
artifacts did not outlive their allocation.

| file | what it answers |
|---|---|
| `RESULTS_helixon_4hop.md` | the Qwen3.8-27B campaign — four arms, what ran exactly, caveats, cost |
| `RESULTS_helixon_4hop_qwen35.md` | the Qwen3.5-27B repeat — three arms, and what changes between checkpoints |
| `4hop_cells.csv` | all 49 episodes as one row each: settings, outcome, cost |
| `trajectories/` | the per-step traces, one JSONL per episode — see its README for the schema |
| `RESULTS.md`, `LEDGER.md`, `results.csv` | the earlier DeltaAI campaign |

`4hop_cells.csv` and `trajectories/` are regenerated by `python scripts/export_4hop.py`;
the two `RESULTS_*` files are written by hand. The tables below are the same numbers as
the CSV.

## Settings, in full

Everything below was the same for all 49 episodes. Where a setting has two ends (thinking
is set from the server for the direct arm and from the client for the codex arms), both
are listed, because setting only one silently changes what is being measured.

| | |
|---|---|
| scenes | 0182 0306 0311 0482 0603 0726 0763 — everything that survives `scripts/screen_scenes.py --hops 4 --reachable --min-depth 4 --max-free 0 --no-backwards` |
| seeds | **one per cell**, fixed before launch |
| steps | 300 max; an episode also ends on `agent_esc` (the agent declares completion and the scorer agrees) or `all_milestones` |
| scoring | milestones the checker confirms, out of the trackable ones; milestones already satisfied at spawn are excluded (`milestones_presatisfied`) |
| hint protocol | on (`--milestone-hint`); premature ESC is refused |
| temperature | 0.7 (client-sent on the direct arm, server default on the codex arms) |
| top_p / top_k | 0.8 / 20, server default |
| output cap | **1024 tokens, server-side** (`--override-generation-config max_new_tokens`) — the only cap that reaches both channels, since codex sends none and vLLM takes the min for the direct arm |
| thinking | **off on both channels**: server `--default-chat-template-kwargs '{"enable_thinking":false}'` for `vllm`, `CODEX_LOCAL_EFFORT=none` for `codex` |
| context window | 131072, matching `DEFAULT_CONTEXT_WINDOW` in `prolong_mc/codex_backend.py` |
| images | server `--limit-mm-per-prompt image:128`; `default`/`hypothesis` attach a 20-frame buffer per step, `prolong` one frame per analyzer turn |
| per-call ceiling | none on `vllm`; `CODEX_TIMEOUT=900` for `prolong` (never reached); **120 s for `default × codex`**, one ceiling then a no-op — a policy that bounds that arm's score |
| codex sandbox | `prolong_mc/codex_sandbox.sh` — bwrap, workspace-only reads, per-episode `CODEX_HOME` with an empty skills marker, egress allowlisted to the model server. `codex_sandboxed: true` is recorded in every codex result |
| environment | one podman Minecraft sandbox on a230 (`192.168.2.22:8000`), runner on a219 |
| serving | vLLM 0.26, TP=2 per server on a227 A100s, MTP speculative decoding (`num_speculative_tokens: 1`), `--enable-auto-tool-choice --tool-call-parser qwen3_xml` |

Serving layout differs by wave, and this is the one thing that is **not** constant across
all 49 cells:

| wave | arms | layout |
|---|---|---|
| 1 (08-18 14:31–17:11) | Qwen3.8 `default × vllm`, `prolong × codex` | two differently sized servers, TP=4 + TP=2, **no prefix caching** |
| 2 (08-19 00:03–07:42) | Qwen3.8 `hypothesis × vllm`, `default × codex` | three identical TP=2 servers, `--enable-prefix-caching`, cells dealt round-robin |
| 3 (08-19 08:36–10:30) | all three Qwen3.5 arms | same as wave 2, Qwen3.5-27B weights |

So a Qwen3.5-vs-Qwen3.8 comparison is layout-matched only for `hypothesis × vllm`. Prefix
caching moves greedy output at the paraphrase level; at temperature 0.7 with one seed that
is inside sampling noise, but it is why the latency comparison is restricted to that arm.

Checkpoints: `Qwen/Qwen3.8-27B` @ `1d4bf0f2ff60`, `Qwen/Qwen3.5-27B` @ `fc05daec18b0`.
Same architecture field for field, so the two take identical serving flags — the generated
run files differ in exactly two lines (`MODEL_PATH`, `--served-model-name`).

## What these numbers do and do not support

- **The arm ordering repeats across checkpoints.** PRO-LONG leads by two milestones on
  both; the hypothesis DAG is worth zero on both. Cell by cell, 12 of the 21 shared cells
  scored identically and 18 of 21 are within one milestone.
- **The spread is inside the noise.** Five seeds of scene 0306 alone spread 2/4–4/4 for
  PRO-LONG and 3/4–4/4 for the default arm. A two-milestone gap over 28 does not clear
  that. This is a run, not a claim.
- **The scene dominates.** Summed over the arms, per-scene totals barely move between
  checkpoints, and four of seven scenes come out within one milestone across all four
  Qwen3.8 arms.
- **`default × codex` is a lower bound, not a score.** With thinking off it spends each
  call re-examining frames it was already handed; 748 of its 2100 steps ran to the 120 s
  ceiling and stepped a no-op. Raising the ceiling buys time linearly, not milestones.
- **Nothing failed for infrastructure reasons.** Across all 49 cells: 0 `Agent call
  failed`, 0 `env.step failed`, 0 `SandboxViolation`, and `codex_sandboxed: true` in all
  21 codex results. The only tracebacks anywhere are in `default × codex` — 748
  `subprocess.TimeoutExpired` (the ceiling, by design) and 9 `codex exec produced no
  message`, which the retry loop absorbed. And the codex arms could not read the answers:
  across 132 468 rollout lines from 2 280 codex sessions, **none** named a `bench_*` path,
  the scene metadata or the checker, and 47 of 24 096 shell calls reached outside the
  episode workspace, where they found only the bind-mount skeleton.

The informative next round is **seeds, not arms**: 7 scenes × 5 seeds of `default × vllm`
+ `prolong × codex` is about 10 h wall on the three-server layout. Fix n before launching.

## Where the raw cells are

`outputs/<prefix>-<agent>-<channel>-<scene>/<model>/4-hop/<scene>/` on the cluster
filesystem — `c4h-` for Qwen3.8, `q35-` for Qwen3.5. ~23 GB: one episode video per cell,
every frame PRO-LONG attached, every codex rollout. Not in git; `trajectories/` is the
part that is.

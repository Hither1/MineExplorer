| # | date | finding | evidence | confidence | implication |

| 1 | 2026-08-15 | PRO-LONG is a *harness*, not a model: a runner appends every action/observation to `logs.txt`, and a coding-agent CLI (Codex or Claude Code) is invoked each turn with `Read/Write/Bash/Grep`, a persistent `/workspace/`, and one job — write `actions.json` = `{"actions": [...]}`. The runner executes that list, appends the results, and calls again. System prompt ~30 lines. | `prolong_agent/agent/prompts.py`; `environment/runner.py:270-330`; `agent/base.py:56-97` | high | The loop is environment-agnostic. | 2 | 2026-08-15 | The environment seam is already abstract: `BaseEnv.reset/step -> (obs, reward, done)` with a single concrete implementation `ArcAgi3Env`. | `prolong_agent/environment/__init__.py:8-23` | high | A `MineExplorerEnv` slots in without touching the agent backends. |
| 3 | 2026-08-15 | Codex is invoked as `codex exec --json --skip-git-repo-check --ignore-user-config -o /workspace/last_message.txt -m <model> -c model_reasoning_effort=... -s danger-full-access <prompt>`, inside `docker run` with the workspace bind-mounted, on an `--internal` network reaching OpenAI only through a squid allowlist. | 10 | 2026-08-15 | MineExplorer's action is already an LLM-emitted JSON object (`ActionState`: 24 binary keys + `camera[pitch,yaw]` + `hotbars[9]`, validated by pydantic). | `mc_agent/action_space.py:11-118` | high | Maps onto `actions.json` with almost no translation; add `repeat` so one plan spans many env ticks, since Minecraft actions are temporally extended in a way ARC's are not. |
| 11 | 2026-08-15 | `transformers serve` has no prefix caching, and PRO-LONG's prompt grows without bound by design. Each analyzer call is a full Codex turn = several internal LLM calls, each re-prefilling the whole log. | design constraint; baseline measured 13-24 s/step with a 20-frame buffer | medium | The dominant cost risk. | 12 | 2026-08-15 | **Rootless podman cannot work on DeltaAI**, for two independent reasons. On the default NFS graphroot: `processing tar file(lsetxattr /bin: operation not supported)`. Moving the graphroot to node-local NVMe (`/tmp`, xfs) clears that and exposes the real blocker: `/etc/subuid` and `/etc/subgid` have no entry for the user, so only a single UID can be mapped and any image with non-zero-owned files fails — `requested 0:42 for /etc/shadow ... lchown: invalid argument`. | `podman run --rm alpine:3.20`, both with default and with `--root /tmp/dzhang5/pm/s` | high | Needs an administrator to allocate subuid ranges. Not worth pursuing. |
| 13 | 2026-08-15 | Apptainer 1.4.2 works unprivileged (`apptainer exec docker://alpine:3.20 echo ok`), and `--containall` hides `$HOME`/repo/`~/.ssh`. But networking is all-or-nothing: `--network bridge` fails with *"non-root users can only use --network=none unless permitted by the administrator"*, and `none` would also cut the agent off from the local model server. | direct execution on the login node | high | PRO-LONG's `--internal` network + squid allowlist is **not reproducible** here. Apptainer can give filesystem isolation only. |
| 14 | 2026-08-15 | **Codex's own bubblewrap sandbox is the better answer and needs no container.** `codex sandbox -c sandbox_mode="workspace-write"` allows writes in cwd, denies writes outside (`Read-only file system`), and denies network to spawned commands (`curl` to the local server returns rc=7). The codex process itself sits outside the sandbox and still reaches the model API. | `codex sandbox` probes on the login node; `codex-resources/bwrap` ships with the aarch64 package | high | Achieves exactly PRO-LONG's threat model — the agent cannot reach the game server while the harness can — with no container at all. Requires replacing PRO-LONG's `-s danger-full-access` *and* its `--dangerously-bypass-approvals-and-sandbox` on the resume path. |

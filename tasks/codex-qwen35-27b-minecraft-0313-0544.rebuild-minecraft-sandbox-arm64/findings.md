| 1 | 2026-08-15 | Podman 4.9.5 is installed and usable on the DeltaAI login node, but cannot run the sandbox: it executes on the same aarch64 kernel and `--arch amd64` yields `exec format error` (no qemu-x86_64 binfmt handler; `/proc/sys/fs/binfmt_misc/` holds only `register`/`status`). | `podman run --rm --arch amd64 docker.io/library/hello-world` | high | The blocker is architecture, not the container engine. | 2 | 2026-08-15 | Rootless podman has no subuid/subgid range for `dzhang5`, so any image containing files with non-zero GID fails to unpack: `lchown /etc/shadow: invalid argument (requested 0:42)`. | `podman pull docker.io/library/alpine:3.19` | high | Even a hypothetical arm64 image could not be unpacked by podman here; a container route needs admin action. |
| 3 | 2026-08-15 | Podman's default graphRoot in NFS home fails with `lsetxattr: operation not supported`; a local-disk root (`/tmp`) is required. | `podman info` graphRoot backing filesystem `nfs` | medium | Secondary; only matters if a container route is ever revived. |

| 5 | 2026-08-15 | The simulator engine ships only as a prebuilt fat jar `engine/build/libs/mcprec-6.13.jar` (466 MB, Minecraft 1.16.5 + OptiFine + MineRL/Malmo hooks, Java 8 bytecode, assets embedded). | 6 | 2026-08-15 | The jar's LWJGL is **3.2.2**, whose bundled natives (`liblwjgl.so`, `libglfw.so`, `liblwjgl_opengl.so`, `libopenal.so`, `libjemalloc.so`) are all x86-64 only. | 7 | 2026-08-15 | DeltaAI login node already provides the full headless graphics stack for aarch64: `/usr/bin/Xvfb`, Mesa `libGLX_mesa`/`swrast_dri.so` (llvmpipe), plus NVIDIA aarch64 `libGLX_nvidia`/`libEGL_nvidia` 595.71.05. | 8 | 2026-08-15 | **The real engine boots on aarch64.** `java -cp <lwjgl-3.3.3 + arm64 natives>:mcprec-6.13.jar net.minecraft.client.main.Main --envPort=29999` under Xvfb reaches `***** Start MalmoEnvServer on port 29999`. Two changes were required: (a) LWJGL 3.3.3 jars ahead of the fat jar on the classpath (`-cp`, not `-jar`), (b) `-Dorg.lwjgl.system.allocator=system`, because GH200's 64 KiB page size makes LWJGL's bundled jemalloc abort with `Unsupported system page size`. | `/work/nvme/bdrx/dzhang5/mc-arm64/run/mc2.log`; crash report of the pre-fix run in `run/mc.log` | high | No source rebuild and no container are needed. Remaining risk moves entirely to the Python/MineStudio layer. |
| 10 | 2026-08-15 | The published x86 image contains **no VirtualGL/`vglrun` and no NVIDIA GL libraries** — only `usr/bin/Xvfb` and Mesa (`swrast_dri.so`, `libGLX_mesa`). So the official sandbox also renders through Mesa's software rasterizer, the same path the aarch64 port uses. | layer scan: Xvfb in layer 17, Mesa/swrast in layer 13; no vglrun anywhere in 41 layers | high | Rendering-path equivalence is much stronger than feared; the port does not silently switch to a different renderer. Mesa *version* still differs and remains unverified. |
| 11 | 2026-08-15 | `~/.local/lib/python3.10/site-packages` is on `sys.path` inside the conda prefix, so the first `pip install` treated leaked user-site packages (`lxml`, `Pillow`, …) as already satisfied and skipped them. The env then imported fine interactively but failed under `PYTHONNOUSERSITE=1`. `psutil` is additionally an undeclared MineStudio dependency. | first Slurm smoke failed on `ModuleNotFoundError: psutil`; isolated import then failed on `lxml` | high | Every sandbox entry point must export `PYTHONNOUSERSITE=1`, and provisioning must install under the same isolation, or the env is not reproducible. |
| 12 | 2026-08-15 | The engine requires **JDK 8**, not DeltaAI's system JDK 11. Under Java 11 the client boots and renders, but Malmo's `EnvServerSocketHandler` dies with `NoClassDefFoundError: javax/xml/bind/JAXBException` (JAXB was removed from the JDK in 11), and OptiFine loses `sun.misc.SharedSecrets`/`jdk.internal.misc` reflection. Temurin 8u502 has an aarch64 build, matching the image's `java-1.8.0-openjdk`. | run `20260815-180657-mc-arm64-sim-smoke-2080` stdout; `jdk8/jdk8u502-b07/bin/java -version` | high | `launchClient.sh` takes `MINEEXPLORER_JAVA`; every entry point pins the bundled JDK 8. |
